# 🍣 SushiDay Astana — онлайн-заказы через WhatsApp

Мобильный каталог с корзиной, формой доставки и отдельной панелью управления. Построен на HTML/CSS/JavaScript, без сборщиков и тяжёлых зависимостей.

**Витрина:** https://manfr0mHorde.github.io/sushi/ (после включения GitHub Pages)  
**Админ-панель:** https://manfr0mHorde.github.io/sushi/admin.html

## Что уже работает

- Адаптивная витрина с категориями, поиском, карточками и количеством товаров.
- Корзина с пересчётом суммы, предложение добавить напиток или соус.
- Форма: имя, телефон, доставка/самовывоз, адрес, подъезд, квартира, способ оплаты, необязательный телефон Kaspi для выставления счёта, комментарий и согласие на передачу данных.
- Готовое сообщение с составом и общей стоимостью открывается в WhatsApp ресторана. Клиент **сам нажимает кнопку «Отправить»**.
- Кнопка копирования текста заказа.
- Админ-панель для добавления, редактирования, скрытия и удаления товаров, управления ценами, фотографиями, категориями, WhatsApp, адресом, доставкой и демонстрационным предупреждением.
- В карточках сетов отображается вес, количество штук (если заполнено) и состав: каждый вид роллов и число штук. Нажатие «Подробнее о составе» открывает удобное окно. Если состав не подтверждён — вместо выдуманной начинки честно указано «Точный состав уточняется».
- В админке для каждого сета есть отдельные поля «Количество кусочков» и «Что входит в сет»; одна строка — один вид роллов, например «Название ролла — 8 шт.». Данные автоматически появляются в витрине и в сообщении WhatsApp.
- Исправлено отображение мобильной версии на ширинах 320–768 px: компактные кнопки без emoji-стрелок, новый первый экран и аккуратные карточки товаров. В CI добавлены настоящие Chromium-проверки адаптивной вёрстки и сохранение скриншотов.
- Демо-режим без сервера для показа заказчику. Данные сохраняются только в localStorage текущего браузера.
- Защищённый режим с Supabase Auth и Row Level Security (RLS): опубликованные цены и каталог одинаковы на всех устройствах.

## Посмотреть демо

Локально откройте папку как статический веб-сайт:

```bash
python3 -m http.server 8000
```

Потом перейдите на `http://localhost:8000/` и `http://localhost:8000/admin.html`.

Пока `config.js` не заполнен, админ-панель работает в явно обозначенном **небезопасном локальном демо-режиме**. Не используйте его как реальную админку: изменения локальные, общедоступная страница не имеет пароля, меню не синхронизируется с пользователями.

## Защищённая админка и единый каталог — Supabase

1. Создайте проект на https://supabase.com/.
2. Откройте SQL Editor и выполните весь файл `supabase.sql`.
3. В Authentication → Users добавьте пользователя администратора с email и надёжным паролем.
4. Скопируйте UUID созданного пользователя и выполните в SQL Editor:
   ```sql
   insert into public.admins(user_id)
   values ('UUID-ADMIN-ACCOUNT-HERE');
   ```
5. В настройках Authentication отключите публичную регистрацию, если новые аккаунты должны создавать только сотрудники.
6. В Supabase → Project Settings / API найдите Project URL и **publishable / anon** key. Вставьте в `config.js`:
   ```js
   window.SUSHIDAY_CONFIG = {
     supabaseUrl: "https://PROJECT.supabase.co",
     supabaseAnonKey: "PUBLIC_ANON_OR_PUBLISHABLE_KEY"
   };
   ```
   Публичный anon / publishable key разрешён в браузере **только благодаря RLS**. Никогда не вставляйте туда `service_role`, secret key или пароль БД.
7. Откройте `admin.html`, войдите учёткой сотрудника. Нажмите «Загрузить примеры» (необязательно) или добавьте свои товары. В «Настройках» укажите проверенный WhatsApp ресторана и цены доставки.
8. Когда меню, составы, цены и изображения проверены, снимите галочку с предупреждения о демо-ценах.

Политики RLS разрешают посетителям читать только видимые товары и контактные настройки. Все изменения защищены проверкой UUID из таблицы `admins`. **Защита работает на сервере**, а не через скрытый пароль в браузерном коде.

Если после настройки каталог не загружается, проверьте, что Supabase Data API включено, схема `public` доступна и что использован правильный publishable/anon ключ.

## GitHub Pages

В репозитории включён workflow `.github/workflows/deploy.yml`. Чтобы опубликовать:

1. Откройте GitHub → **Settings → Pages**.
2. В Build and deployment укажите **Source: GitHub Actions**.
3. В разделе **Actions** выполните / повторите workflow **Deploy SushiDay Pages**.
4. После успешной публикации ссылка: https://manfr0mHorde.github.io/sushi/.

Для будущих изменений достаточно push в ветку `main`.

## Как работает заказ

Например, клиент выбрал «Сет Ассорти» ×2 и «Coca-Cola» ×1. Указал имя, телефон, адрес и оплату Kaspi. Сайт проверяет заполнение и собирает текст:

```text
🍣 НОВЫЙ ЗАКАЗ • SUSHIDAY
1. Сет Ассорти × 2 — 26 780 ₸
2. Coca-Cola × 1 — 1 150 ₸
Товары: 27 930 ₸
Доставка: уточнить
Имя: ...
Телефон: ...
Адрес: ...
Оплата: Kaspi
Пожалуйста, подтвердите наличие, итоговую стоимость и время заказа.
```

Если WhatsApp ресторана заполнен, откроется `https://wa.me/<номер>?text=<готовый текст>`. **Это не автоматическая отправка, приём рестораном или списание денег.** Без заполненного WhatsApp откроется WhatsApp Share, где пользователь сам выбирает адресата. Действие «Скопировать текст» работает отдельно.

Для безусловной автоматической отправки/получения, статусов «Принят», истории заказов, платежных ссылок и оплаты потребуется серверная часть и официальная WhatsApp Business Platform с согласованными шаблонами и условиями использования. Не обрабатывайте на этом сайте номер карты или CVV.

## Перед реальным запуском

Подтвердите с рестораном: точный WhatsApp для заказов, актуальное меню с ценами и фотографиями, адрес, условия доставки/минимальной суммы, рабочие часы, банковские реквизиты/сценарий Kaspi, политику персональных данных. Уточните разрешение на использование логотипа и фирменных фотографий.

Сайт не сохраняет ФИО, телефоны и адреса клиентов в Supabase; данные передаются через ссылку на WhatsApp только после действия пользователя. Корзина хранится локально без персональных данных.


## Обновление: состав сетов и мобильная версия (ноябрь 2026)

**Важно:** в доступном стороннем каталоге есть названия и вес сетов, **но не полный список роллов и количество кусочков внутри**. Придумывать эти данные нельзя. Пока нет официального меню, в витрине показывается «Точный состав уточняется», а поле «Что входит в сет» оставлено пустым. Владелец может внести точные данные для каждого сета из WhatsApp-каталога в админке (каталог → изменить → состав).

Если Supabase настроен **до** этого обновления, откройте SQL Editor и один раз выполните файл `migrations/2026-11-04-set-composition.sql`. Если настраиваете Supabase впервые, новый `supabase.sql` уже включает эти поля.

Проверка мобильной вёрстки выполняется GitHub Actions в Chromium при ширинах 320, 375, 390, 430 и 768 px. Отчёты о переполнениях, кнопках, модальном окне состава, корзине и форме заказа выводятся в лог workflow; PNG-скриншоты сохраняются как артефакт `sushiday-mobile-design-check`.
